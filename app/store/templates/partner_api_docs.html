1 · Autenticación

Se usa tu usuario y contraseña de la tienda. El login devuelve dos tokens JWT: access (válido {{ limits.access_minutes }} min, va en cada petición) y refresh (válido {{ limits.refresh_days }} días, renueva el access sin reenviar la contraseña). Si cambias tu contraseña, todos los tokens anteriores quedan invalidados.

POST/auth/token/

curl -X POST "{{ base_url }}/auth/token/" \
  -H "Content-Type: application/json" \
  -d '{"username": "TU_USUARIO", "password": "TU_CONTRASEÑA"}'

→ {"data": {"tokens": {"access": "...", "refresh": "..."},
            "expires_in": {{ limits.access_minutes * 60 }}, "user": {"id": 7, "username": "TU_USUARIO"}}}

POST/auth/token/refresh/

curl -X POST "{{ base_url }}/auth/token/refresh/" \
  -H "Content-Type: application/json" \
  -d '{"refresh": "..."}'

→ {"data": {"access": "...", "refresh": "...", "expires_in": {{ limits.access_minutes * 60 }}}}

Todas las demás llamadas llevan el header Authorization: Bearer <access>.

5 · Compras

POST/store/purchases/

Pasa por el mismo checkout que la tienda web: valida stock y saldo, entrega las credenciales y descuenta tu saldo. Máximo {{ limits.cart_lines }} líneas y {{ limits.purchases_per_min }} cuentas por minuto.

curl -X POST "{{ base_url }}/store/purchases/" \
  -H "Authorization: Bearer <access>" -H "Content-Type: application/json" \
  -d '{"items": [{"product_id": {{ example_product.id }}, "quantity": 2}]}'

→ {"data": {"cuentas_asignadas": [
      {"producto": "{{ example_product.name }}", "email": "cuenta1@mail.com", "password": "abc123", ...} ],
    "saldo": {"saldo_cop": 101000.0, "saldo_usd": 0.0}}}

Errores típicos: stock insuficiente, saldo insuficiente o producto fuera de catálogo → 400 purchase_failed con el mensaje exacto.

6 · Renovaciones

6.1 · Renovar una cuenta que sigue en inventario

POST/store/renewals/search/ — busca por correo las cuentas renovables.

curl -X POST "{{ base_url }}/store/renewals/search/" \
  -H "Authorization: Bearer <access>" -H "Content-Type: application/json" \
  -d '{"q": "cliente1@mail.com cliente2@mail.com"}'

→ {"data": {"renewable": [ {"account_id": 501, "email": "cliente1@mail.com", "product_id": {{ example_product.id }}, ...} ],
            "rejected":  [ {"email": "cliente2@mail.com", "message": "..."} ]}}

Luego compra esas cuentas pasando sus IDs (una unidad por ID):

{"items": [{"product_id": {{ example_product.id }}, "renovacion_account_ids": [501]}]}

6.2 · Renovar la cuenta del propio cliente (productos que lo permiten)

{"items": [{"product_id": {{ example_product.id }}, "es_renovar_cuenta_cliente": true,
  "customer_email": "cliente@mail.com", "customer_password": "suclave"}]}

→ la solicitud queda pendiente y el administrador la completa (no es entrega instantánea).

En la tabla de productos, la columna «Renueva cuenta del cliente» dice qué productos lo aceptan.

7 · Reportes de cuentas (garantía)

POST/store/issues/ — reporta una cuenta que compraste (caída, clave cambiada, etc.). Acepta JSON o multipart/form-data con imagen (JPG/PNG/WEBP…, máx. 15 MB). La foto acelera la revisión.

curl -X POST "{{ base_url }}/store/issues/" \
  -H "Authorization: Bearer <access>" \
  -F "account_id=501" \
  -F "issue=No deja iniciar sesión, pide cambiar la contraseña" \
  -F "status_label=caida o suspendida" \
  -F "image=@captura.jpg"

→ {"data": {"reported": true, "account_id": 501, "photo": {"photo_id": 88, "status": "open"},
            "note": "El reporte quedó registrado y el administrador fue notificado."}}

También puedes identificar la cuenta por email en lugar de account_id.

GET/store/issues/ — tus reportes con su estado (open, closed) y la respuesta del proveedor cuando exista.
